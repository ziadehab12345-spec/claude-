# Deploying to Vercel — cairopeople.com

A one-time setup. Follow it in order; each step depends on the one before.

---

## Before you start

**Vercel's free Hobby plan does not permit commercial use.** Its Fair Use
policy restricts Hobby to non-commercial projects, and a company site that
brings in customers is commercial. Vercel can suspend the deployment without
warning.

Two honest options:

| | Cost | Notes |
|---|---|---|
| **Vercel Pro** | $20/month | Same setup as below, no policy risk. Recommended. |
| **Hobby now, Pro later** | Free | Works technically. Accept that it may be suspended, and that a suspension takes the site down until you upgrade. |

Nothing below changes between the two — only which plan you pick in step 2.

---

## 1. Create the database

Vercel does not include Postgres. Use **Neon** (neon.tech), which has a free
tier suitable for this traffic.

1. Create a project, region **Frankfurt (eu-central-1)** — closest to Cairo of
   the free regions, so requests are not crossing the Atlantic.
2. Copy the connection string. It must contain `?sslmode=require`.

Keep it somewhere safe. It is a password.

## 2. Create the Vercel project

1. vercel.com → **Add New → Project** → import `ziadehab12345-spec/claude-`.
2. Framework preset: **Next.js** (detected automatically).
3. Do **not** deploy yet — set the environment variables first.

## 3. Environment variables

In **Settings → Environment Variables**, add these for **Production**:

| Name | Value |
|---|---|
| `DATABASE_URL` | The Neon string from step 1, including `?sslmode=require` |
| `AUTH_SECRET` | Run `openssl rand -base64 48` and paste the result |
| `SITE_URL` | `https://cairopeople.com` |

For **Preview**, add `DATABASE_URL` and `AUTH_SECRET` only. Leave
`SITE_URL` unset there: previews then fall back to their own URL and
are automatically excluded from search engines, so they cannot compete with the
real domain in Google.

Never put `SEED_ADMIN_PASSWORD` in Vercel. It is only used once, locally.

## 4. Deploy

Push to `main`, or press **Deploy**. Then check:

```
https://cairopeople.com/api/health
```

Expected: `{"status":"ok","database":"ok",...}`.

If it says `degraded`, the response names what is wrong — a missing variable by
name, or `database: "unreachable"`.

## 5. Create the schema and load the catalogue

Run once, from your own machine, pointed at the production database:

```bash
DATABASE_URL='<the Neon string>' npm run db:migrate
DATABASE_URL='<the Neon string>' \
SEED_ADMIN_EMAIL='you@cairopeople.com' \
SEED_ADMIN_PASSWORD='<a long password you choose>' \
npm run db:seed
```

The seed creates the administrator account only if no user exists yet, so it is
safe to re-run later to refresh catalogue copy.

**Sign in at `https://cairopeople.com/ar/dashboard` and change that password.**

## 6. Point the domain

1. Vercel → **Settings → Domains** → add `cairopeople.com`.
2. Add `www.cairopeople.com` too and let Vercel redirect it to the apex.
3. At your registrar, set the records Vercel shows. Usually:
   - `A` record on `@` → `76.76.21.21`
   - `CNAME` on `www` → `cname.vercel-dns.com`
   Use whatever Vercel displays; it is authoritative.
4. DNS takes anywhere from minutes to a few hours. Vercel issues the HTTPS
   certificate automatically once it resolves.

## 7. After the first deploy

- Google Search Console: add the property, submit
  `https://cairopeople.com/sitemap.xml`.
- Point an uptime monitor at `/api/health`, not at the homepage — the homepage
  can render fine while the database is down.
- Check a link preview by pasting the URL into WhatsApp. It should show the
  gold-on-black card with the Arabic wordmark.

---

## Rolling back

Vercel keeps every deployment. **Deployments → the last good one → Promote to
Production.** This is instant and does not touch the database.

A database change is not covered by that. Migrations here are forward-only, so
take a Neon branch or snapshot before running a new one against production.

## Routine operations

**Refresh catalogue copy after editing `db/catalogue.ts`:**
```bash
DATABASE_URL='<production>' npm run db:seed
```
Safe to re-run. It never changes prices or whether a service is active.

**Add a staff account:** Dashboard → Staff accounts. Never by SQL — the
password must go through bcrypt.

**Reset a forgotten admin password:** another admin can do it from Staff
accounts. If nobody can sign in, run the seed against a database with no users,
or update `password_hash` with a bcrypt hash generated by
`node -e "console.log(require('bcryptjs').hashSync('new-password',12))"`.
